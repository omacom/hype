# Translations

Hype's window follows the language picked under Omarchy's **Setup > Language**, live: English plus Omarchy's 49 translations. Each language has a catalog, `src/i18n/<code>.json`, a flat JSON object from English source text to its translation, compiled into the binary through `src/resources.qrc`. A counted string, `qsTr("%Ln slides selected", "", count)`, maps to an object of plural forms keyed by CLDR category (`{"one": "%Ln slide selected", "other": "%Ln slides selected"}`), and each language gives exactly the categories its counts reach, by the rules in `Translator::pluralCategory`. A string a catalog doesn't have yet shows in English (a regional catalog such as `pt-BR` falls back to `pt` first).

The window and the export worker it starts are translated, so an export's progress and errors arrive in the window's language. The commands (`hype check`, `hype render`, `hype export`) and the command-line exports never install the translator: their output is read by scripts and agents, and stays in English. Slides are the author's and are never translated or mirrored; `slidesRenderTheSameRightToLeft` checks that a right-to-left desktop draws them exactly as written.

`src/translator.h` and `src/translator.cpp` are the copy every Omarchy app carries, byte for byte, from the omarchy-app skill's templates. Change them there, not here.

## Adding or changing a string

Pull requests only ever touch English: wrap the text in `qsTr()` (QML) or `tr()` (C++), with `%1` placeholders filled by `.arg()` rather than a sentence glued together, and add it to `src/i18n/en.json` as itself, or with its `one` and `other` forms when it's counted. A free function in C++ uses its file's `tr()` helper. The `englishCatalogMatchesTheSources` test keeps `en.json` exactly in step with the sources. Leave the other catalogs alone. Since the English is the key, rewording a string makes a new key; its translations become pending, and the old key is dropped by the next sync. The catalog tests check the translations that are there (placeholders, plural forms, language codes, every catalog listed in `resources.qrc`), but never require them to be complete, so English is never blocked.

## Keeping translations in sync

The `Sync translations` workflow (`.github/workflows/i18n-sync.yml`) does the converging, the way Omarchy's, Folio's and Signed's do. It runs on pushes to `master` that change `src/i18n/en.json`, daily, and on demand. `scripts/i18n-sync.py pending` lists, per language, the strings that are missing or whose translation no longer fits, and the keys `en.json` no longer has. Then:

1. One runner per pending language, holding only the Muse key and no repository credentials, runs `translate --locale <code>`. Muse only returns text: the script validates every value and writes that one catalog, dropping keys English no longer has. Whatever fails stays pending.
2. A collect job, with no credentials, takes from each runner only its own `<code>.json`, keeps its current and valid entries, and runs the catalog tests against the result in an Arch container.
3. A land job, holding the `I18N_SYNC_TOKEN`, runs no repository code: it checks that applying the patch staged nothing but edits to catalogs already here (never `en.json`, nothing created, deleted, renamed or given another mode), commits it to the `i18n-sync` branch, and opens and merges an `Update translations` pull request. The next run rebuilds that branch from `master`, so a sync pull request is never left open.

A language that failed, or a run that broke, just leaves strings pending for the next run. The same script works locally: `python3 scripts/i18n-sync.py pending` shows the queue, and `translate --locale da` fills one language with a local Muse.

Repository settings this needs:

- `MUSE_API_KEY`, an Actions secret for the translation runners.
- `I18N_SYNC_TOKEN`, an Actions secret holding a fine-grained PAT with Contents and Pull requests read and write on this repository, for the bot that opens and merges the sync pull request. Without it the workflow falls back to its own token, which can still open and merge the pull request, but GitHub runs no CI on a pull request that token opens.
- Optionally `MUSE_MODEL`, an Actions variable naming the Muse model (default `muse-spark-1.3-contributor`).

## Translator brief

The brief Muse gets lives in `scripts/i18n-sync.py` (`BRIEF`); it applies to people translating by hand too. Keep the name Hype, and translate "slide", "presentation", "overview", "presenter view" and "speaker notes" the way the language's presentation software names them. Write like the interface was made in the language: short, natural, the register of consumer desktop software. Keep exactly: product and brand names, file formats and names, the `images/` and `videos/` folders, the words an author types into a slide (`span`, `fit`, an `svg` block, `--name` theme colors), key names and symbols, units, and placeholders: `%1` to `%9` and `%Ln` must all be there, though they may be reordered. In a plural entry, `other` keeps every placeholder, and another form may drop `%Ln` only where the language says that number with a word. `pt` is European Portuguese and `pt-BR` Brazilian; `sr` is Serbian in Cyrillic.
